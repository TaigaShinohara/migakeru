# 真っ白画面の修正記録（v0.4.1 診断 → v0.4.2 修正 → v0.4.3 仕上げ）

## 症状（2026-11-22、本人が実機スクショで報告）

v0.4.0 を開くと背景グラデーションだけが表示され、文字・カード・タブが一切出ない。

## 診断（v0.4.1）

静的解析では断定できなかったため診断版を交付：

- 起動処理を try/catch で包み、例外時はエラー内容を画面に描く（今回は例外なし）。
- 初回レイアウト後に寸法を自己診断し、異常時のみ画面に重ねて表示。

実機の診断表示：`モード ob / ob_done=false / root=1280x2856 / ob子=1 / ob=1280x0`

→ オンボーディングのコンテナ（縦 LinearLayout の weight=1 子）が **高さ0** に潰れていることが確定。子（ページの ScrollView）は存在するのに描画領域がない。メイン画面も同じ構造のため同じ故障のはず。

## 修正（v0.4.2、本人が「直った」と確認）

- weight 子を廃止し、土台を **FrameLayout の重ね方式**に総入れ替え（背景・コンテンツ・バーはすべて MATCH_PARENT、バーは gravity で上下に寄せ、重なり回避はパディング）。
- showScreen / renderObPage の addView にも MATCH_PARENT を明示。
- 起動エラーの画面表示と自己診断（異常時のみ表示）は安全網として残置。

## 仕上げ（v0.4.3）

- 本人から「ちょっと見切れてる」と指摘：edge-to-edge で最上段（バディ行）がステータスバーの時計に潜っていた。
- WindowInsets の systemBars 上インセットを、コンテンツ側の上パディングに加算（メイン／オンボーディング上部バー／オンボーディング本体）。

## 教訓

- この端末・この構造では weight 子の高さが0になる。新しい画面は最初から FrameLayout 重ねで組む。
- 実機でしか起きない故障は「例外の画面表示＋寸法の自己診断」で1往復で特定できる（このVMにはエミュレータ／KVMがない）。
