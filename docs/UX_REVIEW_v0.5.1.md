# UX独立審査 v0.5.1 — 「飽き・挫折しない親切さ」

- 対象版：v0.5.1（versionCode 11、コミット 246a468）
- 審査日：2026-11-25
- 審査範囲：途中で飽きたり挫折しないように親切な設計になっているか（初回〜数か月継続の時間軸）
- 審査方式：独立審査（作成者と別の担当が、仕様正本・実装・現行画面・選出ロジックの再現シミュレーションで審査）。審査環境の注記：審査者は文脈を部分的に共有するため完全分離ではない。その分、判定は数値検証可能な形で出させ、作成者側でも独立に再現確認した（下記「照合」）。
- 変更区分：審査のみ（実装は本記録の後の本人判断で範囲を決める）

## 判定：不合格

「責めない」設計（挫折させない側）は積極的に成立している（維持判定 G1〜G7）。しかし数か月継続の時間軸では2点で破綻する：

1. **U1（必須）**：卒業提案を受け入れ続けた最も熱心なユーザーが約3週間で起動エラー画面に到達し、アプリ内に復旧手段がない。
2. **U2（必須）**：卒業でプールが痩せるのに補充がなく、バディのセリフは全4種固定、図鑑は読み切り。新しさの供給が構造的にゼロで、使うほど単調になる。

## 照合（作成者側の独立再現、2026-11-25）

選出ロジックを再現したシミュレーションで審査者の数値主張を検証した：

- U1：全項目を毎日完了し卒業提案をすべて受け入れる条件で、**21日目に「こころ」プールが空になり例外**（審査者の主張と一致）。
- U3：卒業なし・180日で「髪を整える」の提示は **3回**（他は44〜45回）。審査者の主張（1〜2回）とは開始日依存の差があるが、「事実上出現しない」という結論は一致。

## 指摘

### U1柱プールの全卒業で起動不能になる（詰み状態）
- 根拠：`MigakeruLogic.pickToday` が候補の空の柱で `require` を投げ、`onCreate` の try/catch 経由でスタックトレース付きエラー画面になる。以後毎回同じ画面で、アプリ内復旧手段なし（復旧＝OS設定からデータ消去のみで全記録喪失）。全完了＋卒業全受諾のシミュレーションで21日目に到達。卒業提案は今日画面と鏡画面の両方に主ボタンで表示される本道の先の破綻。既存テストは卒業集合を常に空で渡し、枯渇経路を検証していない。
- 解消条件：どの柱も候補が空にならないことが構造的に保証されること（残り2項目は卒業提案を出さない／補充が入る／pickToday のフォールバック、のいずれか）。あわせて「卒業を受け入れ続ける90日シミュレーション」で例外なく3項目提示が続く回帰テストがあること。

### U2卒業でプールが痩せる一方、補充がなく、終盤は「毎日同じ項目」になる
- 根拠：プールは からだ5／みため5／こころ4 の計14項目。仕様 §4 は「新しい候補は図鑑と連動して1つだけ補充」を定めるが §10 で後回しとされ、現行版に補充経路なし。図鑑の「今日の候補に入れる」ボタン（仕様 §5.3）も未実装。柱の残り1項目になると毎日同じ項目が提示され、残り2項目では実質交互になる。U1 を避ける代償がこの単調化で、どちらを選んでも長期体験が壊れる。
- 解消条件：卒業と同数以上の新規候補が供給される仕組み（図鑑連動の補充、予備プール等）が実装され、長期シミュレーションで各柱のローテーション幅が維持されること。

### U3選出ローテーションに偏りがあり「髪を整える」がほぼ出現しない
- 根拠：決定論ローテーション `pool[dayOfYear % pool.size]` と直近3日回避フィルタの位相の噛み合い。180日で「髪を整える」は3回のみ（同柱の他項目は44〜45回）。オンボーディングの「ひと通りまんべんなく回る」という宣言とも一致しない。
- 解消条件：選出が「最も長く出ていない項目優先」のような均等化ロジックになり、180日シミュレーションで全項目の提示回数の偏りが一定範囲に収まる回帰テストがあること。

### U4バディのセリフが全4種固定で、状態に一切反応しない
- 根拠：`greetingForHour` は時間帯別の4文のみ。全完了の日も、数週間ぶりの復帰の日も、卒業の日も同じ文。仕様 §5.1 の「文言プール」は未実装。バディはアプリの感情的な顔であり、その無反応は「頑張りが返ってくる」感覚の中核の欠落。
- 解消条件：完了時・全完了時・復帰時・卒業時など状態に応じたセリフがプールから出ること（最低でも完了反応と全完了反応があり、同文の連続表示が起きないこと）。

### U5完了タップの瞬間のフィードバックが無音
- 根拠：今日画面のカードタップは記録切替＋再描画のみで、称賛文・触覚・バディ反応がない。取り消し時にだけトーストが出る非対称。オンボーディング側は弾み＋触覚＋称賛文まで備えており、核の報酬ループ「タップ→できた」の瞬間が本体では最も静か。
- 解消条件：完了タップに、その場で分かる正の反応（触覚＋一言など、オンボーディング試し操作と同水準）が返ること。

### U6差し替えの対象を選べない
- 根拠：差し替え対象は最初の未完了項目に固定。今日できないのが2・3番目の項目だと差し替えられない。また変更先が直近に提示済みの項目になりうる（swapCandidate は recent を見ない）。
- 解消条件：未完了の各項目から差し替え対象を選べること（1日1回の制限は維持可）。

### U7卒業までの進捗が見えず、しかも静かに減る
- 根拠：卒業判定は直近21日で5回の移動窓。進捗表示はカウント3〜4の項目だけが今日画面の最下部一言に出るのみで、0〜2は不可視。間が空くと古い完了が窓から落ち、カウントが説明なく減る（表示自体が消える）。累計表示（わたし画面）は減らない設計で問題は卒業までの距離の見え方に限る。
- 解消条件：各項目の卒業までの進捗が任意に確認でき、窓の仕様が分かる形（例：「直近21日で○回」の明示）になっていること。

### U8図鑑は1行×12枚の読み切りで、増えず、プールとも繋がっていない
- 根拠：本文は全12枚とも1文程度で、仕様 §5.3 の想定より薄い。既読管理も追加供給もなく、初週に読み終えたら再訪理由がない。U2 の補充経路としても機能していない。
- 解消条件：図鑑から候補プールへの追加導線があること、または再訪理由のある再定義（段階開放等）があること。

### U9実績のあるユーザーの「ゼロの週」にだけ、鏡が無言
- 根拠：労いの文（「ここに、できた日が並んでいく」）は生涯記録ゼロの新規ユーザーにしか出ない。数週間空けて復帰したユーザーのゼロの週には受け止め文がなく、○○○と「0個」だけが並ぶ。
- 解消条件：記録のあるユーザーのゼロ週にも、責めない受け止めの一言が添えられること。

## 維持判定（良い点として維持すべきもの）

- **G1** 持ち越し・連続記録（ストリーク）の完全な排除。何日空けても復帰コストゼロで、復帰画面は通常日と同一。鏡は「量」表示で未来日は「これから」と区別。
- **G2** 責めない文言の全面徹底。非難・催促の語がなく、赤色・未達マークもない。通知自体が未実装で催促経路が存在しない。
- **G3** 全完了で「今日はもう十分」に切り替わり、それ以上を要求されない着地点がある。
- **G4** 卒業は提案制で可逆（戻せる）、バッチは残り続け、わたし画面の累計は一生減らない。
- **G5** 差し替えボタンに対象→変更先が押す前に明記される予測可能性。1日1回の制限が決断疲れを防ぐ。
- **G6** オンボーディングの最初の成功の保証（試し操作＝本物の記録、「あとで試す」も完了扱い、スキップ常時表示、3択目の逃げ道、称賛文の非重複ローテーション）。
- **G7** 完了はいつでも取り消せる誤タップへの寛容。鏡の一言は任意・1行で書かされ感がない。
